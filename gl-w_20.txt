20. GRUB
     Como se explicó anteriormente, GRUB es básicamente el primer software
que corre en la computadora, dándole el control del sistema al kernel.
     Es "multiboot", oseáse que puede ser el gestor de arranque para más de
un sistema operativo.
     Hoy en día se usa GRUB 2, quedando GRUB (se le dice GRUB Legacy) casi
obsoleto hoy en día.
     El nombre del gestor de arranque de Linux es GNU GRUB, aunque se le
dice directamente GRUB, y ya.
     GRUB se encarga tanto de lo del kernel como de funcionar como un sistema
operativo minimalista, permitiendo elegir qué sistema cargar en la memoria con
ciertas instrucciones predeterminadas que nosotros, los usuarios, podemos
cambiar.

PARÁMETROS DE ARRANQUE 
     A la hora de elegir el sistema, abajo hay un mensaje que dice varias
cosas, entre ellas que si presionamos "e" podemos editar los comandos
de la carga. Vamos a ver que hay varias líneas que al principio van a
resultar confusas pero más que nada es por la combinación de números y
letras que hay. Por ahora nos vamos a centrar en la siguiente línea:

      linux /boot/vmlinuz-(version)-(archtecture) root=UUID ro quiet

* linux /boot/vmlinux... : acá se menciona la ubicación del kernel, que tiene
el número de versión seguido de la arquitectura:
* root=... : en este caso se especifica el UUID (Universally Uniqued
IDentifier) del dispositivo de almacenamiento en donde se va a montar el
sistema de archivos raíz (root). 

 (cada dispositivo de almacenamiento posee un UUID único que viene a ser una
larga cadena de letras y números)

     A partir de este punto, se pueden agregar parámetros opcionales:
* debug: muestra mensajes de diferentes procesos en el arranque, y es útil a
la hora de diagnosticar y solucionar problemas.
* ro: monta el sistema de archivos raíz como solo lectura (read-only).
* rw: como "ro", pero montándolo con pemriso de escritura además de lectura
(read-write).
* quiet: no imprime ningún mensaje durante el arranque, a excepción de los
extremadamente necesarios.
* loglevel=n: cantidad de mensajes que aparecen, pudiendo n tener un valor
del 0 al 7.
* init=... : se especifica el primer proceso que se quuiere ejecutar en vez
de systemd o el que sea que esté de manera predeterminada.
* selinux[0 or 1]: activa o desactiva SELinux (Security-Enhanced Linux), que
consiste en un sistema de seguridad implementado en el kernel que establece
ciertas políticas y regulaciones estrictas sobre lo que pueden hacer los
usuarios y dónde pueden acceder.
* nousb: no carga ningún dispositivo conectado mediante entrada USB.
* mem=... : se puede aclarar la cantidad de memoria máxima que puede usar el
kernel, expresado en un número seguido o de M (Megabytes) o G (Gigabytes).
* nomodeset: hace que el kernel no cargue los controladores de video, como el
GPU.
* panic=n: reinicia automáticamente el sistema n segundos después de pasado
el "kernel panic".
* elevator=... : al kernel de Linux le podemos asginar un "gestor de tareas"
de entrada y salida (I/O scheduler) y establece el orden en el que las
operaciones de I/O necesarias van a ser ejecutadas almacenamiento. Puede
tener como valor: "deadline" (predeterminada), "noop" (no operation), o "cfq"
(Complete Fairness Queueing) (no sé qué es pero ahora no me interesa),
entre otras.

VALORES PREDETERMINADOS
     Ahora nos vamos a centrar en el archivo "/etc/default/grub", el cual solo
se puede editar con permisos de super-usuario. De las varias lineas que hay,
voy a mencionar las siguientes:
GRUB_TIMEOUT=n: espera n segundos antes de arrancar automáticamente el sistema
cuyo índice esté establecido en GRUB_DEFAULT. Si no queremos que pase esto,
hay que poner la opción "-1".
GRUB_DEFAULT=n: establece el sistema que se va a ejecutar automáticamente
después de pasados los segundos en GRUB_TIMEOUT si no se elige otra opción.
Se basa en el índice que tiene el sistema en la lista, empezando por 0, que es
el valor predeterminado.
GRUB_CMDLINE_LINUX=... : acá se pueden escribir los diferentes parámetros de
arranque anteriormente mencionados para TODOS los diferentes sistemas que se
puedan iniciar.
GRUB_CMDLINE_LINUX_DEFAULT=... : parecido al anterior, pero esta vez las
opciones son solamente para el sistema operativo cuyo índice sea elegido en
GRUB_DEFAULT.
GRUB_GFXMODE=resolution : permite cambiar el tamaño del menú, cosa útil para
computadoras con una alta resolución en el cual las letras de GRUB son tan
grandes como hormigas.

     Por último, pero no menos importante, para que los cambios tomen efecto,
hay que ejecutar:
$ sudo update-grub


KERNEL PANIC
     Ya que lo mencioné, lo explico...
     Se puede ver que el kernel es como el corazón de un sistema operativo, y
lo demás son todos los otros órganos. Si el kernel se llega a encontrar con
un error el cual no puede manejar, ya seaa producido por algún bug del kernel
mismo, o algo del hardware, o alguna mala configuración del sistema, entra
en un estado de "pánico", en el cual para evitar daños irreversibles,
"congela" el sistema, protegiéndolo.
